# Deviations and verification status

- The runtime is wired through the installed PacketEvents API only. login-core does not initialize or shut down PacketEvents itself, and no AuthMe plugin/API is required.
- `CipherInstaller` uses small local Netty message handlers around JDK `Cipher` instances. The Netty version resolved by Paper has no public `CipherDecoder` or `CipherEncoder` classes at the imports suggested in the original plan.
- `com.hizeric.logincore.handshake.LoginFlowState` names the plugin's per-connection state machine to avoid colliding with PacketEvents' own `ConnectionState` enum.
- AuthMe's `AsyncPlayerPreLoginEvent` exposes an `InetAddress`, not a Netty channel identity. The short-lived verified-session handoff therefore indexes by normalized name and remote IP while retaining the unique connection ID for removal, one-shot consumption, and expiry.
- Existing accounts default to `REQUIRE_PASSWORD_ONCE`; `DENY` is the explicit alternative (`ADOPT` was dropped). New premium identities are registered locally with a randomly generated password that is not disclosed to the player.
- Premium UUID mode defaults on and applies the Mojang UUID only after successful session verification. It does not migrate UUID-keyed player data; cracked and exempt logins retain Paper's offline UUID.
- The premium player profile is applied at `EventPriority.LOWEST` on `AsyncPlayerPreLoginEvent`, separately from the registration/auto-login work that stays at `HIGHEST`. LuckPerms pre-loads permission data at `LOW`, keyed by `AsyncPlayerPreLoginEvent#getUniqueId()` (which returns the mutable profile UUID). Applying the profile later made LuckPerms load data under the offline UUID, then look for the Mojang UUID at `PlayerLoginEvent`, and deny the join with "Permissions data for your user was not loaded during the pre-login stage".
- The runtime-name flip to `AuthMe` is complete (ADR 0008): `plugin.yml` uses `name: AuthMe`, `depend: [packetevents]`, and the data folder is `plugins/AuthMe/authme.db`. The `authme` table schema is unchanged for compatibility. Dev installs with an older `data.db` must rename it (and its `-wal`/`-shm` siblings) to `authme.db` before starting.
- AuthMe is no longer a runtime or compile dependency: `AuthMeBridge`, `fr.xephi:authme-core` and the AuthMe event handlers were removed; password login/registration and the `LoginEvent`/`RegisterEvent` compatibility events are implemented in login-core. The Phase 5 exit criterion "no external AuthMe plugin dependency; standalone jar builds" is met at build time.
- Netty handler names in `CipherInstaller` are `logincore-decrypt`/`logincore-encrypt`; they are identity labels, not runtime coupling. The `mempalace.yaml` wing name remains historical.
- Skin forwarding was removed because the server uses a separate skin-restoration plugin. login-core no longer reads or applies the Mojang `textures` property.
- Build-only verification is recorded here. Live premium/offline E2E is owned by the separate cutover gate and is not claimed by this change; see [SPIKE_RESULTS.md](./SPIKE_RESULTS.md).
- FastLogin and AuthMe were used as behavioral/API references only; their implementation source was not copied into this project.
